Root cause: CoreSales offered preview/capture using role and sale stage alone.
Unlike the ExtendedSales controls, its context omitted the existing enrollment
check. The database correctly rejected capture, but only after the user had
reviewed a preview and clicked its enabled action.

result. Unenrolled sales show an explicit read-only explanation instead of
editable Core Sales actions. Preview requests fail with HTTP 403 before a legal
snapshot is prepared; capture rechecks enrollment so an older signed preview
cannot bypass removal of eligibility. The original database capture guard,
role checks, private evidence rules and integration delivery block remain intact.
No migration, RLS change, enrollment or UI redesign was made.
