Navigation
All detail links originating from the register carry an allowlisted snagList query containing building, search, status, source, responsibility, exact unit if supplied, sort and original page. It is query state, never a page-limited ID array or external return URL.
Detail navigation rereads the full authorised building list through the existing authenticated API. That API already reads across backend pagination. Both the register and navigation use the same selectSnags helper before the register slices 20-row pages. Stable snag IDs resolve neighbours. Default floor/unit order comes from the unchanged API; the new sort selector also offers oldest/newest raised, with stable ID tie-breaking.
The same list context survives further chevrons, reloads, new-tab links and Back to snags. The breadcrumb also returns to that context. There is no new global state.
Previous/next use icon-only buttons with accessible names and tooltips. Boundaries hide the corresponding button. Direct links without valid same-building context hide both. Missing/deleted/no-longer-matching records show a list-navigation notice instead of choosing an arbitrary neighbour. Read failures hide controls and retain the return route. Saves and window focus trigger a fresh list read; obsolete requests are aborted. Existing detail access checks remain authoritative if a record changes between read and click.
