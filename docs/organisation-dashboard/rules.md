# Dashboard rule catalogue

All rows below are derived presentation over persisted state and existing business calculations. Nothing here introduces a legal gate or SLA. `D` = developer team; `A` = recorded sales-agent organisation; `C` = conveyancer organisation; `K` = responsible contractor. Visibility always requires existing RLS and module permission first. Ownership never grants access. Actions remain in existing authorised workflows.

Common freshness rule **F**: opening/scope change, successful relevant mutation, stale focus/reconnect or visible 60-second poll rereads the summary. Source failure is unavailable/partial; failed network refresh may show explicitly stale prior data. Counts use the complete authorised population, not the first ten displayed rows. Missing waiting timestamps are labelled unknown; fallback creation dates never become current-cycle age. Date-only deadlines use London calendar dates; exact authority expiry uses its timestamp.

Portfolio summaries count sale-route unit states (five principal stages plus unreleased/retained), active developer snags separately from resident defects, active/occupied/void rental units, current required document reviews, approved unpaid invoices and eligible handovers. Their values are unavailable when their source fails. Sales and rental membership may overlap; no combined unique inventory is claimed. Buildings need not have snags to appear.

Recent activity uses actual projected business milestones, within a start-inclusive/end-exclusive seven London calendar-day window. Domain IDs deduplicate the projection; generic audit events are not loaded alongside it. At most seven latest entries are displayed, each with a sale activity destination. It excludes logins, heartbeats and unit views and never determines outstanding work.
